# 一、产品定义与开发边界

## 1.1 产品概述

文案轻工坊是一款基于微信小程序的固定场景 AI 文案生成工具。

用户无需掌握 Prompt 编写方法，只需要选择文案模板、填写必要信息，即可获得可编辑、可复制、可保存的文本结果。

产品主要面向：

1. 自媒体创作者：快速生成标题、脚本和社交文案。
2. 职场人士：辅助完成周报、会议纪要和工作邮件。
3. 学生用户：辅助完成作文构思和论文大纲，不代写完整论文。

产品不提供开放式聊天，不发展为通用 AI 助手。

## 1.2 V1.0 核心目标

| 目标编号 | 目标 | 验收依据 |
|---|---|---|
| G01 | 完成固定场景 AI 文案生成 | 10 个模板全部可用 |
| G02 | 建立用户账户和额度体系 | 免费及付费额度正确计算 |
| G03 | 实现商业化支付闭环 | 微信支付、订单、额度发放正常 |
| G04 | 支持内容管理 | 历史、复制、编辑、保存、删除可用 |
| G05 | 支持基础运营 | 后台可管理模板、套餐、用户和订单 |
| G06 | 满足生产运行要求 | 具备安全审核、日志、告警和恢复机制 |

## 1.3 功能范围冻结

### P0：本期必须开发

- 微信登录与用户账户。
- 首页、分类页、模板表单页、结果页。
- 10 个固定 AI 模板。
- AI 生成、重新生成、结果改写。
- 复制、编辑、保存、历史记录、删除。
- 免费额度、次数包、月度额度包。
- 微信支付、订单查询、退款处理。
- 管理后台、模板配置、运营数据。
- 内容审核、限流、异常处理、隐私管理。
- 监控、告警、自动化测试及基础高可用部署。

### P1：下一版本候选，不得提前开发

- 公众号短文案。
- 标题优化。
- 月报、简历润色、述职报告、面试介绍。
- 读后感构思、读书笔记。
- 辅助风险词检测。
- 合同简易草稿（须先完成法律风险评估）。

### Out of Scope：本期明确禁止开发

- 通用 AI 聊天或自由多轮对话。
- AI 图片、视频、音频生成。
- 语音转文字、录音上传、文件解析。
- 实时联网搜索、热点抓取。
- 自动发布到小红书、抖音、公众号等平台。
- 完整论文代写、虚构参考文献或实验数据。
- 企业版、多租户、团队协作。
- 自动续费、邀请返佣、签到积分。
- 广告变现、社区、社交关系。
- RAG、向量数据库、模型训练或微调。
- 原生 App、H5 用户端、PC 用户端。

**强制开发约束：任何不在 P0 清单中的功能，AI 编程工具不得自行新增页面、接口、数据库表或第三方依赖。**

# 二、用户角色与权限

## 2.1 角色定义

| 角色 | 标识 | 主要权限 |
|---|---|---|
| 游客 | `guest` | 浏览首页、分类、模板介绍、套餐介绍 |
| 普通用户 | `user` | 生成文案、管理历史、查看额度、购买套餐 |
| 运营管理员 | `operator` | 查看业务数据、管理模板、查询用户和订单 |
| 超级管理员 | `super_admin` | 运营权限及退款、套餐调整、账号管理 |
| 企业客户 | 暂不支持 | V1.0 无企业专属功能 |

用户首次进入小程序时不强制提供手机号、昵称或头像。

用户首次点击生成、保存、查看个人记录或购买套餐时，完成必要的微信身份识别及隐私告知流程。

## 2.2 权限规则

- 游客不能调用 AI 生成接口。
- 普通用户只能查看和操作自己的记录。
- 普通用户不能访问后台 API。
- 运营管理员不能执行退款和管理员权限调整。
- 超级管理员执行敏感操作时必须经过二次确认。
- 所有后台写操作必须记录操作人、时间、操作类型及变更摘要。

# 三、产品信息架构

## 3.1 小程序导航结构

底部 TabBar 固定为三个入口：

| Tab | 名称 | 路由 |
|---|---|---|
| 1 | 首页 | `/pages/home/index` |
| 2 | 历史 | `/pages/history/index` |
| 3 | 我的 | `/pages/me/index` |

其他页面通过普通页面跳转进入，不增加底部 Tab。

## 3.2 页面清单

| 页面编号 | 页面名称 | 路由 | 登录要求 |
|---|---|---|---|
| U01 | 首页 | `/pages/home/index` | 否 |
| U02 | 模板分类页 | `/pages/templates/index` | 否 |
| U03 | 文案生成页 | `/pages/generate/index` | 提交时需要 |
| U04 | 生成结果页 | `/pages/result/index` | 是 |
| U05 | 历史记录页 | `/pages/history/index` | 是 |
| U06 | 套餐购买页 | `/pages/plans/index` | 支付时需要 |
| U07 | 我的订单页 | `/pages/orders/index` | 是 |
| U08 | 我的页面 | `/pages/me/index` | 部分功能需要 |
| U09 | 设置与数据管理页 | `/pages/settings/index` | 数据操作需要 |
| U10 | 协议详情页 | `/pages/legal/index` | 否 |

登录确认、额度不足、删除确认、支付异常等采用弹窗或页面内状态，不单独增加页面。

## 3.3 核心业务流程

### 流程 A：首次生成

打开小程序 → 首页 → 选择模板 → 填写表单 → 点击生成 → 必要的登录与隐私确认 → 服务端校验额度 → 提交生成任务 → 查看结果 → 复制或保存。

### 流程 B：额度不足

点击生成 → 服务端确认无可用额度 → 展示额度不足弹窗 → 用户选择购买套餐或返回 → 支付成功 → 返回原生成表单 → 用户确认后重新提交。

**支付成功不得自动触发 AI 生成，防止用户不知情消耗额度。**

### 流程 C：再次生成

结果页 → 点击“重新生成” → 提示将消耗 1 次额度 → 用户确认 → 创建新任务 → 返回新结果。

### 流程 D：文案改写

结果页 → 点击“改写” → 跳转到“文案润色改写”模板 → 自动填入当前结果 → 用户选择改写目标 → 提交新任务。

### 流程 E：购买套餐

套餐页 → 选择套餐 → 创建待支付订单 → 调起微信支付 → 用户完成支付 → 后端确认支付结果 → 发放额度 → 更新账户余额。

# 四、全局交互与设计规范

## 4.1 页面通用状态

所有涉及网络请求的页面必须支持以下状态：

| 状态 | 展示规则 |
|---|---|
| 初始状态 | 展示页面基础结构 |
| 加载中 | 显示骨架屏或局部加载指示 |
| 加载成功 | 展示业务数据 |
| 空数据 | 显示说明文案和可执行操作 |
| 网络异常 | 提示“网络连接异常，请重试” |
| 服务异常 | 提示“服务暂时不可用，请稍后重试” |
| 登录失效 | 重新完成登录，不清空已填写表单 |
| 权限不足 | 提示无权限，不展示敏感数据 |

不得出现无限旋转的加载动画且没有退出方式。

## 4.2 全局按钮规范

- 所有主要操作按钮必须具备正常、按下、禁用、加载中四种视觉状态。
- 提交请求后立即禁用重复提交。
- 需要消耗额度或删除数据的操作必须明确提示后果。
- 复制、保存等操作成功后显示短暂反馈。
- 破坏性操作不得使用无确认的一键执行方式。
- 触控区域建议不小于 44 × 44 CSS 像素的等效可点击尺寸。
- 不使用仅靠颜色区分成功与失败的提示。

## 4.3 通用输入规则

- 所有文本字段提交前执行首尾空白清理。
- 必填文本仅包含空格、换行时视为未填写。
- 字符长度按 Unicode 码点计数，前后端采用同一规则。
- 文本输入不得执行用户提供的脚本或 HTML。
- 禁止用户输入直接拼接为系统级 Prompt。
- 输入超长时在字段下方展示具体限制。
- 校验失败时自动定位到第一个错误字段。
- 不在客户端持久化存储支付密钥、模型密钥等敏感数据。

## 4.4 通用文案

| 场景 | 提示文案 |
|---|---|
| 必填为空 | 请填写{字段名称} |
| 内容超长 | 最多输入{N}个字符 |
| 网络失败 | 网络连接异常，请重试 |
| AI 失败 | 本次生成失败，未扣除额度 |
| 额度不足 | 当前可用次数不足，请购买套餐 |
| 内容不适合生成 | 当前内容暂不支持生成，请修改后重试 |
| 复制成功 | 已复制到剪贴板 |
| 保存成功 | 已保存到我的文案 |
| 删除成功 | 已删除 |
| 支付待确认 | 正在确认支付结果，请稍后刷新 |
| 系统繁忙 | 当前使用人数较多，请稍后重试 |

具体错误由服务端错误码决定，不直接展示模型供应商返回的原始错误信息。

# 五、用户端页面详细需求

# U01：首页

## 5.1 页面目标

让用户在最短路径内找到需要的文案场景，并了解剩余可用额度。

## 5.2 页面模块

| 模块 | 字段或内容 | 交互 |
|---|---|---|
| 顶部标题 | 文案轻工坊 | 静态展示 |
| 产品说明 | 选择场景，填写信息，快速生成文案 | 静态展示 |
| 额度区域 | 今日免费剩余次数、付费剩余次数 | 点击进入套餐页 |
| 分类入口 | 自媒体、职场、学生 | 点击进入分类页 |
| 热门模板 | 运营配置的固定模板列表 | 点击进入对应生成页 |
| 底部导航 | 首页、历史、我的 | 切换 Tab |

热门模板为固定配置列表，不开发个性化推荐算法。

## 5.3 按钮行为

**“自媒体 / 职场 / 学生”**

点击后打开 U02，并传入对应分类参数。

**“热门模板卡片”**

点击后进入 U03，传入有效模板 ID。

**“查看额度 / 购买次数”**

进入 U06。游客可以查看套餐，但支付前需要登录。

## 5.4 异常状态

- 模板列表请求失败：显示重试按钮。
- 某模板已下架：不显示该模板入口。
- 额度请求失败：首页仍可浏览，额度显示“暂时无法获取”。
- 用户未登录：额度区域展示“登录后查看额度”。

## 5.5 验收标准

- AC-U01-01：三个分类入口均跳转正确。
- AC-U01-02：已下架模板不在首页出现。
- AC-U01-03：游客可正常浏览首页。
- AC-U01-04：额度异常不影响模板浏览。
- AC-U01-05：底部三个 Tab 导航正确。

## 5.6 页面目标

按固定业务场景展示可用模板。

## 5.7 页面字段

| 字段 | 类型 | 规则 |
|---|---|---|
| 当前分类 | 枚举 | 自媒体 / 职场 / 学生 |
| 模板名称 | 文本 | 服务端返回 |

# U03：文案生成页

## 5.11 页面目标

通过动态表单收集必要信息并创建 AI 生成任务。

## 5.12 页面模块

| 模块 | 内容 |
|---|---|
| 模板信息 | 名称、说明、适用场景 |
| 动态表单 | 根据模板配置生成输入控件 |
| 辅助说明 | 字段提示、字数限制、填写示例 |
| 额度提示 | 本次成功生成预计消耗 1 次 |
| 主按钮 | 立即生成 |
| 辅助按钮 | 清空内容 |

## 5.13 按钮详细行为

### 按钮：立即生成

触发顺序：

1. 校验所有必填字段。
2. 校验字段长度和枚举值。
3. 检查是否已登录。
4. 若未登录，完成必要登录流程。
5. 向服务端提交生成请求。
6. 服务端检查模板状态、风险、限流和额度。
7. 创建生成任务并预占 1 次额度。
8. 跳转 U04，展示任务进度。

按钮提交后立即进入禁用状态。

客户端重复点击不得创建多个任务。

### 按钮：清空内容

点击后弹窗：

“确定清空当前填写的内容吗？”

- 取消：保持表单。
- 确定：恢复当前模板默认值。

若所有字段为空或为默认值，可直接恢复而不弹窗。

### 按钮：返回

- 表单未修改：直接返回。
- 表单已修改：提示“离开后未提交的内容将丢失”。
- 选择继续填写：关闭弹窗。
- 选择离开：返回上一页。

## 5.14 生成任务状态

| 状态 | 状态码 | 页面展示 |
|---|---|---|
| 已创建 | `queued` | 正在排队 |
| 生成中 | `running` | AI 正在生成文案 |
| 成功 | `succeeded` | 展示完整结果 |
| 审核拒绝 | `rejected` | 提示修改输入，释放额度 |
| 失败 | `failed` | 提示失败，释放额度 |
| 超时 | `timed_out` | 提示超时，释放额度 |

任务创建后不可由页面返回操作直接取消。

离开生成页或关闭小程序后，服务端任务继续执行。用户可通过历史记录恢复查看。

## 5.15 异常处理

| 异常 | 处理方式 |
|---|---|
| 字段缺失 | 原页提示，不发送请求 |
| 未登录 | 完成登录后保留表单 |
| 额度不足 | 弹出套餐购买入口 |
| 模板下架 | 禁止提交，提示返回选择 |
| 内容审核不通过 | 不生成、不扣费 |
| 请求超时但服务端已创建任务 | 通过幂等 ID 查询原任务 |
| 当前已有运行中任务 | 引导查看现有任务 |
| 网络断开 | 保留输入，允许查询或重试 |
| 系统维护 | 提示稍后再试，不扣费 |

## 5.16 验收标准

- AC-U03-01：全部 10 个模板的表单可正常渲染。
- AC-U03-02：必填、字数、枚举校验准确。
- AC-U03-03：未登录用户完成登录后不丢失表单。
- AC-U03-04：连续点击只创建一个生成任务。
- AC-U03-05：额度不足时不会调用 AI。
- AC-U03-06：内容审核拒绝不扣费。
- AC-U03-07：离开页面后任务仍可查询。
- AC-U03-08：已下架模板不能创建新任务。

# U04：生成结果页

## 5.17 页面目标

展示 AI 结果，并提供编辑、复制、保存、改写和重新生成功能。

## 5.18 页面结构

| 模块 | 内容 |
|---|---|
| 状态区域 | 生成中 / 成功 / 失败 |
| 模板信息 | 本次使用的模板名称 |
| AI 标识 | AI 生成内容，仅供参考 |
| 结果正文 | 可选择、可复制的纯文本 |
| 主操作 | 复制文案 |
| 辅助操作 | 编辑、保存、改写、重新生成 |
| 额度信息 | 本次成功生成消耗 1 次 |

不展示模型内部推理过程，不展示原始 Prompt。

## 5.19 按钮：复制文案

- 复制当前页面展示的正文。
- 如果用户已经编辑，则复制编辑后的内容。
- 复制成功提示“已复制到剪贴板”。
- 复制失败提示“复制失败，请重试”。
- 不消耗额度。

## 5.20 按钮：编辑

点击“编辑”后：

- 正文切换为多行文本编辑区域。
- 展示“完成编辑”和“取消编辑”按钮。
- 最大允许 5,000 个字符。
- 不触发 AI 请求。
- 不消耗额度。

点击“完成编辑”：

- 保留当前编辑文本在页面内。
- 提示用户可点击保存以持久化。
- 不自动覆盖原始 AI 结果。

点击“取消编辑”：

- 无改动：退出编辑模式。
- 有改动：弹出放弃修改确认框。

用户离开页面时，如存在未保存的编辑内容，必须提示确认。

## 5.21 按钮：保存

- 将当前正文保存到“我的文案”。
- 保存内容可以是原始结果，也可以是用户编辑后的结果。
- 对同一生成任务重复保存时，更新该任务关联的已保存内容，不重复创建多条收藏记录。
- 保存成功后按钮状态改为“已保存”。
- 后续编辑后再次保存，更新已保存版本。
- 不消耗额度。

## 5.22 按钮：改写

- 打开 T05“文案润色改写”模板。
- 自动填入当前展示文本。
- 用户选择改写目标。
- 由用户再次确认提交。
- 成功改写消耗 1 次额度。

若当前文本超过 T05 输入上限，提示用户先缩短内容，不自动截断。

## 5.23 按钮：重新生成

点击后弹窗：

“重新生成将使用相同的输入信息，并在成功后消耗 1 次额度。是否继续？”

- 取消：无操作。
- 确定：创建新任务。
- 新任务拥有独立任务 ID。
- 原结果和历史记录不被覆盖。

## 5.24 失败结果展示

失败时不展示空白结果框。

显示：

- 失败原因的用户可理解描述。
- “本次未扣除额度”。
- “返回修改”按钮。
- “重试生成”按钮（仅对可重试错误展示）。

审核拒绝时不提供无条件重复提交按钮，应引导用户修改输入。

## 5.25 验收标准

- AC-U04-01：成功结果完整展示。
- AC-U04-02：复制内容与当前显示文本一致。
- AC-U04-03：本地编辑不扣额度。
- AC-U04-04：保存后可在历史页查看。
- AC-U04-05：重复保存不产生重复收藏。
- AC-U04-06：重新生成成功只扣 1 次。
- AC-U04-07：失败结果不扣额度。
- AC-U04-08：离开未保存编辑内容时有确认。
- AC-U04-09：不同用户不能通过修改 jobId 查看他人结果。

# 六、10 个 AI 模板的字段级需求

## 6.1 模板引擎统一规则

所有模板使用同一动态表单引擎。

模板配置至少包括：

- `templateId`
- `name`
- `category`
- `description`
- `status`
- `version`
- `fields`
- `outputConfig`
- `promptVersion`
- `maxInputChars`
- `maxOutputTokens`

模板 ID 永久唯一；已使用的模板 ID 不允许重新分配给不同业务场景。

模板字段支持：

- 单行文本 `text`
- 多行文本 `textarea`
- 单选 `select`
- 布尔选项 `boolean`

不开发文件上传、富文本编辑器和复杂嵌套表单。

## 6.2 字段类型通用定义

| 字段类型 | UI | 校验 |
|---|---|---|
| `text` | 单行输入框 | 必填、字符长度 |
| `textarea` | 多行输入框 | 必填、字符长度 |
| `select` | 单选控件 | 必须属于允许的枚举 |
| `boolean` | 勾选控件 | 仅允许 true / false |

下表中的字段长度均为首期建议值，可在开发前统一确认。上线后调整不得破坏旧模板版本的历史记录。

# 七、额度、计费与套餐业务规则

## 7.1 额度单位

一次成功完成的 AI 生成任务消耗 1 次额度。

以下操作不消耗额度：

- 浏览模板。
- 填写表单。
- 查看历史。
- 复制结果。
- 手动编辑。
- 保存或删除文案。
- 输入审核拒绝。
- AI 生成失败或超时。
- 输出审核未通过且未交付结果。

以下操作成功后消耗 1 次额度：

- 首次生成。
- 重新生成。
- 改写生成。

## 7.2 免费额度规则

- 每个已识别微信用户每日获得 5 次免费额度。
- 每日按照北京时间 00:00 重置。
- 当日未使用额度不累计至次日。
- 不允许通过退出登录重复领取。
- 免费额度以服务端记录为准。
- 仅依赖客户端计数无效。

## 7.3 付费额度规则

**50 次包：**

- 支付确认后发放 50 次。
- 首期默认无固定有效期。
- 不允许转赠或跨账户转移。

**30 天 300 次包：**

- 支付确认后发放 300 次。
- 从支付成功时间起有效 30 × 24 小时。
- 到期后剩余次数失效。
- 不自动续费。
- 重复购买形成独立额度批次，不覆盖旧额度。

## 7.4 额度使用优先级

统一采用：

**最早到期的可用额度优先消耗；到期时间相同则先获得的额度优先。**

示例：

- 免费额度当晚到期，月度包 10 天后到期：优先使用免费额度。
- 月度包今天 18:00 到期，免费额度今天 24:00 到期：优先使用月度包。
- 无到期时间的 50 次包：通常最后使用。

用户不手动选择额度来源。

## 7.5 额度预占与最终扣减

生成任务使用三阶段状态：

`reserved` → `consumed` 或 `released`

处理规则：

1. 服务端验证可用额度。
2. 在数据库事务中预占 1 次。
3. 创建唯一生成任务。
4. AI 成功且输出通过审核后，确认消耗。
5. 任务失败、超时或审核拒绝，释放预占。
6. 所有操作记录额度流水。

额度不足和任务创建必须在并发场景下保持一致。

## 7.6 并发与限流

首期建议：

- 每个用户同时最多 1 个未结束的 AI 生成任务。
- 每个用户最多 10 次生成请求 / 10 分钟。
- 每个用户最多 50 次成功生成 / 自然日。
- 全局限流根据服务负载动态配置。
- 触发限制时显示清晰提示，不预占额度。

上述属于防滥用限制，付费页面必须清楚披露适用规则。上线前应通过真实用户测试评估是否影响正常使用。

## 7.7 额度边界验收

- AC-CREDIT-01：每日免费额度最多 5 次。
- AC-CREDIT-02：北京时间跨日后额度正确重置。
- AC-CREDIT-03：并发提交不会出现负余额。
- AC-CREDIT-04：同一任务不会重复扣费。
- AC-CREDIT-05：失败任务自动返还预占。
- AC-CREDIT-06：过期额度不能继续使用。
- AC-CREDIT-07：付费额度发放和使用均有流水。
- AC-CREDIT-08：重复购买月度包不会覆盖已有额度。

# 八、支付、订单与退款业务规则

## 8.1 订单状态

| 状态 | 含义 |
|---|---|
| `created` | 已创建，待支付 |
| `paying` | 支付处理中 |
| `paid` | 已确认支付成功 |
| `closed` | 订单已关闭 |
| `refund_pending` | 退款处理中 |
| `refunded` | 已完成退款 |
| `refund_failed` | 退款处理失败，待跟进 |

## 8.2 支付关键规则

- 订单号由服务端生成，必须全局唯一。
- 金额由服务端根据套餐配置计算。
- 客户端不能修改实际支付金额。
- 支付回调必须验证签名、订单归属、金额及状态。
- 订单状态更新和权益发放必须保证幂等。
- 支付成功但额度发放失败时，必须进入自动补偿或人工告警流程。
- 定时对账任务核对支付平台与本地订单。
- 用户主动查询订单可触发安全的支付状态核对。

## 8.3 退款规则

V1.0 采用人工审核与微信支付退款接口结合的处理方式。

- 未使用的付费权益可按已公示售后规则申请处理。
- 已部分使用的订单根据实际使用情况、售后政策和适用法律审核。
- 退款成功后，必须同步处理剩余权益。
- 不得出现“已全额退款但额度仍可继续使用”的情况。
- 不得简单宣称所有数字服务一律不退款。
- 退款金额、处理期限及特殊情形须在上线前由运营和法律专业人员确认。

退款处理应记录申请原因、审核人、处理时间、支付平台退款单号及额度调整流水。

## 8.4 支付验收

- AC-PAY-01：真实支付成功只发放一次权益。
- AC-PAY-02：重复回调不重复入账。
- AC-PAY-03：支付取消不发放权益。
- AC-PAY-04：金额异常不发放权益。
- AC-PAY-05：回调丢失后可通过主动查询恢复状态。
- AC-PAY-06：退款后权益调整准确。
- AC-PAY-07：订单、支付记录、额度流水可相互核对。

# 九、AI 生成引擎与内容安全

## 9.1 AI 生成流程

服务端处理顺序：

1. 校验用户身份。
2. 校验模板及参数。
3. 执行输入内容风险检查。
4. 检查额度和频率限制。
5. 创建任务并预占额度。
6. 组装模板 Prompt。
7. 调用 AI 模型。
8. 校验输出结构和长度。
9. 执行输出内容风险检查。
10. 保存结果。
11. 确认扣减额度。
12. 将任务标记为成功。

若中间发生失败，必须进入明确的补偿流程。

## 9.2 Prompt 规则

每个模板必须拥有：

- 独立系统指令。
- 独立输入字段映射。
- 独立输出格式要求。
- 字数或 Token 上限。
- 安全约束。
- Prompt 版本号。

用户输入仅作为业务数据，不得覆盖系统级规则。

## 9.3 生成结果规范

- 返回纯文本内容。
- 不执行 AI 输出中的脚本或 HTML。
- 不向用户展示内部 Prompt。
- 不展示模型 API Key。
- 不暴露模型供应商内部错误。
- 对生成结果进行 AI 内容标识。
- 对学生场景实施专门的输出边界检查。

## 9.4 任务超时与重试

首期建议：

- AI 任务总体处理超时：60 秒。
- 可重试的临时错误：最多重试 1 次。
- 不对审核拒绝、参数错误或权限错误自动重试。
- 同一任务内部重试不得重复扣费。
- 任务最终失败时释放额度。
- 超时任务的迟到模型响应不得再次变更已终结的任务状态。

客户端在结果页查询任务状态，前 30 秒每 2 秒查询一次，之后每 5 秒查询一次，直到任务结束或到达页面等待上限。

用户离开页面后不继续无意义轮询。

## 9.5 内容审核

至少包含：

- 输入文本审核。
- 输出文本审核。
- 学术代写限制。
- 违法违规及明显高风险内容拦截。
- 用户输入和输出的长度控制。
- 模型异常输出检查。

对风险内容采用“拒绝本次生成 + 不扣费 + 可理解提示”的处理方式。

不能将“违禁词检测”视为完整内容安全体系，也不能承诺第三方平台审核必然通过。

## 9.6 模型成本控制

服务端记录：

- 模板 ID。
- 模型供应商及模型版本。
- 输入 Token。
- 输出 Token。
- 请求耗时。
- 成功或失败状态。
- 估算成本。
- 错误分类。

管理员可配置模型调用预算和异常告警阈值。

达到系统保护阈值时可暂停新任务并提示维护，不能继续预占后无限等待。

# 十一、接口需求与数据模型

## 11.1 接口统一约定

- 使用 HTTPS。
- 用户端采用 REST API。
- 请求和响应使用 JSON。
- 服务端统一鉴权和参数校验。
- 所有创建型关键接口支持幂等。
- 成功响应统一使用 `code`、`message`、`data`、`requestId` 封装，业务字段放在 `data` 中。
- 错误响应使用统一错误码。
- 客户端不直接访问数据库。
- 客户端不直接调用大模型。

## 11.2 核心用户接口

| 方法 | 路径 | 功能 |

## 11.3 创建生成任务请求示例

```json
{
  "templateId": "XHS_TITLE",
  "templateVersion": 1,
  "clientRequestId": "unique-request-id",
  "inputs": {
    "topic": "周末城市徒步",
    "audience": "年轻上班族",
    "sellingPoints": "路线轻松、适合新手",
    "style": "真实"
  }
}
```

### 响应示例

HTTP `202 Accepted`：

```json
{
  "code": "OK",
  "message": "任务已提交",
  "data": {
    "jobId": "job_123",
    "status": "queued",
    "estimatedCreditCost": 1
  },
  "requestId": "server-request-id"
}
```

`clientRequestId` 由客户端生成，并在网络重试时保持不变。服务端通过用户 ID 和请求 ID 的联合唯一约束避免重复任务。

## 11.4 生成任务状态查询响应

```json
{
  "code": "OK",
  "message": "查询成功",
  "data": {
    "jobId": "job_123",
    "status": "succeeded",
    "templateId": "XHS_TITLE",
    "result": {
      "text": "1. 周末去城市里走走\n2. 新手也能轻松走的城市路线\n3. 用一场徒步放慢周末\n4. 适合周末的轻松城市徒步\n5. 从散步开始探索城市",
      "structured": {
        "items": [
          { "title": "周末去城市里走走", "angle": "场景型" },
          { "title": "新手也能轻松走的城市路线", "angle": "新手型" },
          { "title": "用一场徒步放慢周末", "angle": "感受型" },
          { "title": "适合周末的轻松城市徒步", "angle": "推荐型" },
          { "title": "从散步开始探索城市", "angle": "探索型" }
        ]
      },
      "schemaVersion": "1.0",
      "aiGenerated": true
    },
    "creditsConsumed": 1,
    "createdAt": "2026-10-19T08:00:00Z",
    "completedAt": "2026-10-19T08:00:12Z"
  },
  "requestId": "server-request-id"
}
```

未成功时 `data.result` 不应包含可作为成功结果使用的内容。

成功结果同时提供 `text` 和 `structured`：服务端先按任务绑定的模板输出 Schema 校验模型返回，再从校验后的结构生成可复制、可保存的 `text`；`structured` 仅包含校验通过的模板 `result` 数据，供结果页按模板展示和分别复制。`schemaVersion` 标识该结构的版本，旧任务继续使用创建时固定的版本。客户端不得通过拆分 `text` 推断候选项或其他结构。用户手动编辑只更新保存内容，不覆盖原始 AI 结构化结果。

# 十二、非功能需求与高可用标准

## 12.1 性能目标

| 指标 | 初期目标 |
|---|---|
| 普通业务 API P95 | 500ms 以内，不含外部依赖 |
| AI 生成任务 P95 | 20 秒以内 |
| AI 生成成功率 | ≥98% |
| 自有 API 月可用性 | 99.9% |
| 支付权益重复发放 | 0 起 |
| 已知并发额度超扣 | 0 起 |

上述指标属于开发与试运营验收目标，必须通过压测和真实环境监控验证。

## 12.2 高可用架构要求

- API 服务至少两个生产实例。
- AI Worker 与 API 服务独立运行。
- AI Worker 支持多实例消费同一队列。
- 使用托管高可用 PostgreSQL。
- 使用托管 Redis。
- 使用任务幂等和分布式任务状态控制。
- 服务部署支持健康检查与自动重启。
- 模型调用具有超时、有限重试和故障降级。
- 数据库定期备份并验证恢复。
- 配置和模板发布支持回滚。

首期不引入 Kubernetes 和微服务拆分。

## 12.3 数据恢复目标

建议上线前验证：

- 核心业务数据 RPO 目标：不超过 15 分钟。
- 主要业务服务 RTO 目标：不超过 2 小时。
- 订单与额度恢复后必须执行一致性核对。
- 备份恢复至少完成一次演练。

实际可达目标取决于所采购的托管数据库及备份配置，不能仅通过文档宣称实现。

## 12.4 安全要求

- 全站 HTTPS。
- 用户和管理员权限隔离。
- 管理员多因素认证。
- 服务端密钥安全管理。
- 支付回调验签。
- 输入校验与内容审核。
- 接口限流和防重复提交。
- 敏感日志脱敏。
- 生产环境禁止调试接口暴露。
- 数据库最小权限访问。
- 依赖漏洞扫描。
- 数据访问和删除操作可审计。

## 12.5 隐私要求

- 只收集实现业务所必需的数据。
- 不默认要求手机号、真实姓名、头像。
- 用户输入不得未经授权用于训练自有模型。
- 第三方模型处理用户文本的方式必须在隐私告知中说明。
- 明确历史记录保留期限。
- 提供个人数据删除和账户注销路径。
- 对学生及可能涉及未成年人的使用场景落实适用保护要求。

6. 不在前端处理真实支付金额和额度发放。
7. 不直接修改额度余额而不记录流水。
8. 不以客户端支付成功状态作为发放权益依据。
9. 不允许生成失败仍扣除额度。
10. 不允许未经确认修改套餐规则。
11. 不允许用户访问其他用户的文案、订单或额度。
12. 不允许将完整学术论文生成加入学生模板。
13. 所有关键操作必须包含成功、失败、加载和异常状态。
14. 每个模块必须提供可运行的测试。
15. 任何与 PRD 冲突的实现，必须先提出问题，不得自行决定。

**开发交付不等于页面可点击。只有前端、后端、数据库、AI 调用、支付、额度、异常处理、权限、安全与测试形成完整闭环，才算功能完成。**

# 十九、项目完成定义（Definition of Done）

单个功能只有满足以下条件，才允许标记为完成：

- UI 与 PRD 一致。
- 字段及按钮行为完整。
- 服务端接口实现。
- 权限和数据校验完成。
- 加载、空状态、失败状态完成。
- 关键业务规则完成。
- 自动化测试通过。
- 无阻断级缺陷。
- 日志与异常可追踪。
- 经产品验收确认。
