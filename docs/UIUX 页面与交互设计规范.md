## 一、设计目标与定位

### 1.1 产品设计定位

文案轻工坊是一款基于固定场景模板的 AI 文案生成工具。

用户不需要学习复杂的提示词，也不需要与 AI 进行多轮聊天，只需要：

**选择场景 → 填写信息 → 生成文案 → 编辑、复制或保存。**

UI/UX 设计应围绕这条路径展开，减少用户思考成本。

### 1.2 设计关键词

**简洁、精致、轻盈、专业、温和、可信赖。**

整体视觉气质参考：

- 精品文具与数字笔记产品的秩序感。
- 编辑类应用的清晰排版。
- 现代生产力工具的高效交互。
- 适度温暖的品牌细节。

不采用以下容易过时或影响效率的设计：

- 大面积高饱和渐变。
- 玻璃拟态、霓虹光效、复杂 3D 装饰。
- 大量悬浮卡片和重阴影。
- 每个模块使用不同强调色。
- 不必要的轮播图、弹窗和过度动画。
- 大面积插画挤占主要功能区域。

### 1.3 核心体验目标

| 目标 | 设计要求 |
|---|---|
| 上手简单 | 新用户无需教程即可找到模板并开始填写 |
| 视觉耐看 | 主要依赖排版、留白、比例和细节体现质感 |
| 生成高效 | 从首页到提交生成，尽量控制在 3 次主要操作以内 |
| 结果易用 | 复制、编辑、保存入口清晰 |
| 费用透明 | 生成前明确显示额度消耗，失败不扣额度 |
| 状态可信 | 不展示虚假的生成进度或支付成功状态 |
| 适配稳定 | 兼容常见微信小程序设备、刘海屏和安全区 |

## 二、品牌视觉方向

### 2.1 设计主题

**主题名称：轻纸墨绿（Paper & Ink）**

设计概念：

将文案创作理解为在一张干净的纸上整理想法。界面以温和的纸白色作为背景，以深色文字建立阅读秩序，用低饱和墨绿色突出主要操作。

界面应当有品质感，但不抢走用户正在创作的内容。

### 2.2 品牌色彩规范

| Token | 色值 | 用途 |
|---|---|---|
| `color-primary` | `#2F6156` | 主按钮、选中状态、重点交互 |
| `color-primary-hover` | `#264F46` | 主按钮按下状态 |
| `color-primary-light` | `#EDF4F0` | 轻强调背景、标签 |
| `color-background` | `#F7F8F5` | 全局页面背景 |
| `color-surface` | `#FFFFFF` | 表单、内容区域、卡片 |
| `color-text-primary` | `#202824` | 标题、正文 |
| `color-text-secondary` | `#65716B` | 辅助说明 |
| `color-text-placeholder` | `#858E89` | 占位提示 |
| `color-border` | `#E4E9E4` | 分割线、边框 |
| `color-danger` | `#A84343` | 错误、删除 |
| `color-warning` | `#9A6332` | 提醒、额度不足 |
| `color-success` | `#2F6156` | 成功反馈 |

**使用原则：**

1. 约 80% 的页面保持中性背景与白色内容区。
2. 墨绿色只用于主要操作和必要的状态强调。
3. 一个页面通常只出现一个视觉权重最高的主按钮。
4. 不把金色作为常规强调色，避免界面显得商业化或浮夸。
5. 正文文字必须满足可读性要求，不使用过浅灰色。

### 2.3 字体与排版

使用微信小程序系统字体，优先遵循设备原生中文字体表现，不引入额外商用字体依赖。

| 层级 | 字号 | 字重 | 用途 |
|---|---|---|---|
| 页面主标题 | 44–48rpx | 600 | 首页、结果页 |
| 区块标题 | 36rpx | 600 | 页面模块 |
| 卡片标题 | 32rpx | 500–600 | 模板名称 |
| 正文 | 28–30rpx | 400 | 内容、说明 |
| 辅助文字 | 26rpx | 400 | 标签、提示 |
| 次要说明 | 24rpx | 400 | 时间、备注 |

排版规则：

- 正文行高建议为字号的 1.5–1.7 倍。
- 页面主标题与正文之间保持明显层级。
- 不使用连续大段加粗。
- 一行内避免混用三种以上字号或字重。
- 长文案结果优先保证阅读舒适度，而非信息密度。

### 2.4 间距系统

采用基于 8rpx 的间距体系。

| Token | 数值 | 典型用途 |
|---|---|---|
| `space-1` | 8rpx | 图标与文字微间距 |
| `space-2` | 16rpx | 标签间距 |
| `space-3` | 24rpx | 表单字段内部 |
| `space-4` | 32rpx | 页面左右边距 |
| `space-5` | 40rpx | 卡片内部 |
| `space-6` | 48rpx | 模块间距 |
| `space-8` | 64rpx | 大区块分隔 |

页面默认左右边距：**32rpx**。

不建议为每个页面单独发明间距数值。

### 2.5 圆角与阴影

| 组件 | 圆角 |
|---|---|
| 主按钮 | 20rpx |
| 输入框 | 16rpx |
| 模板卡片 | 24rpx |
| 弹窗 | 28rpx |
| 标签 | 12rpx |

阴影仅用于必要的悬浮层。

常规卡片优先采用浅边框或背景层级，不使用明显投影。

### 2.6 图标规范

- 采用统一的线性图标风格。
- 常规尺寸为 36–40rpx。
- 线条粗细保持一致。
- 图标优先辅助理解，不单独承担操作说明。
- 不使用 Emoji 作为正式 UI 图标。
- 主要操作采用「图标 + 文字」组合，避免用户猜测含义。

## 三、页面结构与导航

### 3.1 用户端信息架构

**底部 TabBar 固定三个入口：**

1. 首页
2. 历史
3. 我的

其他页面通过正常导航进入。

| 页面编号 | 页面名称 | 路由 |
|---|---|---|
| U01 | 首页 | `/pages/home/index` |
| U02 | 模板列表 | `/pages/templates/index` |
| U03 | 文案生成表单 | `/pages/generate/index` |
| U04 | 生成结果 | `/pages/result/index` |
| U05 | 历史记录 | `/pages/history/index` |
| U06 | 套餐购买 | `/pages/plans/index` |
| U07 | 我的订单 | `/pages/orders/index` |
| U08 | 我的 | `/pages/me/index` |
| U09 | 设置 | `/pages/settings/index` |

### 3.2 页面层级原则

首页承担发现与进入模板的职责，不直接堆叠大量功能。

历史页承担找回内容的职责。

我的页面承担账户、额度和设置职责。

每个页面保持单一主要目标，减少功能交叉。

## 四、核心组件设计规范

### 4.1 主按钮

**样式：**

- 高度：96rpx。
- 背景：`#2F6156`。
- 文字：白色、30rpx、500 字重。
- 圆角：20rpx。
- 横向宽度：根据场景全宽或自适应。
- 最小触控区域：建议不小于 88rpx。

**状态：**

- 默认：可点击。
- 按下：颜色加深。
- 加载中：显示加载图标与文字，禁止重复提交。
- 禁用：降低视觉权重，并明确禁用原因。
- 成功：通过反馈提示告知结果，不长期改变按钮样式。

主按钮文案必须描述明确动作，例如：

- 开始生成
- 复制文案
- 保存修改
- 确认支付

避免使用含义不清的「确定」「立即体验」。

### 4.2 次级按钮

用于返回、重新填写、取消、查看详情等操作。

优先采用白色底、浅边框、深色文字。

同屏不应出现多个视觉权重相同的按钮。

### 4.3 模板卡片

卡片包含：

- 统一线性图标。
- 模板名称。
- 一句话说明。
- 可选的轻量分类标签。
- 右侧进入箭头。

卡片不要加入过多描述、统计数据或装饰图片。

示例：

**小红书标题**  
把内容亮点整理成 5 个更有吸引力的标题。

### 4.4 表单输入组件

统一使用 TDesign Miniprogram 组件封装。

字段结构：

1. 字段名称。
2. 可选或必填标识。
3. 输入区域。
4. 简短辅助说明。
5. 校验错误信息。

规则：

- 必填项清楚标识。
- 长文本输入框支持自动增高或合理滚动。
- 有字数限制时显示实时计数。
- 校验错误优先显示在对应字段下方。
- 不用仅靠红色边框表达错误。
- 提交后自动定位到第一个不合法字段。

### 4.5 额度展示组件

展示：

**今日免费额度：3 / 5 次**

如有付费额度，可在详情中分开展示：

- 免费额度。
- 已购买额度。
- 最近到期时间。

不要将不同有效期的额度合并成容易误导的「永久余额」。

### 4.6 空状态组件

包含：

- 简单线性插图或小图标。
- 一句清楚的状态说明。
- 一个有价值的行动按钮。

例如：

**还没有生成记录**  
选择一个模板，开始写第一篇文案。

按钮：**去选择模板**

### 4.7 提示反馈

| 类型 | 表现形式 |
|---|---|
| 复制成功 | 轻量 Toast |
| 保存成功 | 轻量 Toast |
| 输入错误 | 字段级提示 |
| 额度不足 | 明确说明 + 查看套餐入口 |
| 删除内容 | 二次确认弹窗 |
| 生成失败 | 页面内错误状态 + 重试操作 |
| 支付结果未确认 | 等待核实页面，不显示成功 |
| 账号注销 | 高风险确认流程 |

## 五、用户端页面详细设计

### U01｜首页

**页面目标：** 让用户快速找到合适的写作场景。

#### 页面布局

自上而下：

1. 顶部品牌名称「文案轻工坊」。
2. 简洁欢迎区。
3. 搜索或分类快捷入口（首版优先分类，不必实现复杂搜索）。
4. 常用模板推荐。
5. 全部模板入口。
6. 额度信息入口。
7. 底部 TabBar。

#### 欢迎区

主标题：

**写得更好，不必从零开始。**

副标题：

选择一个场景，填写想法，轻松生成适合你的文案。

欢迎区使用文字排版建立视觉重点，不使用大面积插画。

#### 模板推荐

首屏优先展示 4–6 个常用模板：

- 小红书标题。
- 小红书文案脚本。
- 短视频口播稿。
- 文字润色。
- 工作周报。
- 朋友圈文案。

其余模板通过「查看全部模板」进入。

#### 交互规则

- 点击模板卡片进入对应生成表单。
- 点击分类进入模板列表并携带分类条件。
- 未登录用户允许浏览模板。
- 点击额度信息时，未登录用户可先进入登录流程。
- 首页不得强制弹出购买弹窗。

#### 页面状态

- 加载中：骨架屏。
- 加载失败：保留页面基础结构，显示重试入口。
- 模板下架：不再展示入口。
- 无推荐模板：显示全部可用模板入口。

---

### U02｜模板列表页

**页面目标：** 帮助用户从 10 个首发模板中快速找到目标。

#### 页面结构

1. 顶部标题「选择写作场景」。
2. 分类筛选栏。
3. 模板列表。
4. 空状态。

#### 分类

- 全部
- 自媒体创作
- 职场办公
- 学习写作

#### 模板展示规则

每个模板展示：

- 名称。
- 简介。
- 图标。
- 分类。

不在模板列表中展示复杂评分、使用次数或虚构热度。

#### 交互规则

- 分类切换不清空页面滚动位置以外的用户数据。
- 点击模板进入 U03。
- 模板不可用时不允许继续提交。
- 不支持的功能不展示灰色入口诱导点击。

### U03｜文案生成表单页

**页面目标：** 让用户以最少的输入获得可用结果。

#### 页面结构

1. 顶部模板名称。
2. 一句话模板说明。
3. 动态表单字段。
4. 可选风格或长度选项。
5. 额度消耗说明。
6. 底部固定「开始生成」按钮。

#### 表单视觉规则

- 字段之间保持 32–40rpx 间距。
- 长文本输入区采用白底与浅边框。
- 必填字段在前，可选字段在后。
- 不同时展开过多高级选项。
- 选择器采用单选按钮组或底部选择面板。

#### 提交按钮上方文案

**本次生成预计消耗 1 次额度。生成失败不扣费。**

实际扣减规则必须以服务端返回为准。

#### 提交流程

1. 点击「开始生成」。
2. 前端校验字段。
3. 未登录则进入微信登录，返回后保留当前表单内容。
4. 服务端校验模板及额度。
5. 提交生成任务。
6. 进入生成中状态。
7. 成功后跳转结果页。

#### 防重复规则

- 提交后按钮立即进入加载状态。
- 同一用户同一时刻仅允许一个运行中的任务。
- 客户端携带 `clientRequestId`。
- 网络重试不得造成重复生成或重复扣费。

#### 生成中状态

页面展示：

**正在整理你的想法…**

辅助说明：

通常需要一点时间，你可以稍候查看结果。

采用轻量呼吸动画或进度指示，但**不显示没有真实依据的百分比进度**。

状态包括：

- 排队中。
- 生成中。
- 内容审核中（如服务端有该状态）。
- 生成成功。
- 生成失败。
- 内容未通过审核。
- 请求超时。

#### 异常处理

| 场景 | UI 处理 |
|---|---|
| 额度不足 | 说明不足原因，提供套餐入口 |
| 输入不合法 | 对应字段下方显示错误 |
| 网络中断 | 提示任务可能仍在处理，可通过历史记录查看 |
| 模型超时 | 告知未扣费，提供重新生成 |
| 内容审核拒绝 | 提示调整输入内容，不展示敏感技术细节 |
| 模板已下架 | 提示返回模板列表 |
| 任务重复提交 | 继续查看已有任务，不再创建新任务 |

### U04｜生成结果页

**页面目标：** 让用户立即使用生成内容。

#### 页面布局

1. 页面标题「生成结果」。
2. 模板名称和生成时间。
3. 文案内容区。
4. 操作区。
5. 额度变化说明。

#### 内容区设计

结果区应具有轻量编辑器质感：

- 白色背景。
- 充足内边距。
- 适合阅读的行高。
- 明确段落分隔。
- 不使用聊天气泡。

对于不同模板，支持不同内容呈现方式：

- 小红书标题：5 条独立标题，分别可复制。
- 小红书脚本：标题、开头、正文、结尾。
- 周报：按工作模块分组。
- 会议纪要：议题、结论、待办事项。
- 邮件：主题、称呼、正文、落款。
- 写作提纲：层级化章节结构。

#### 主要操作

**复制全部**：主按钮。

次要操作：

- 编辑。
- 保存。
- 重新生成。

小红书标题可额外提供「复制此条」。

#### 编辑规则

- 编辑是对已有结果进行本地修改。
- 编辑本身不消耗额度。
- 点击保存后写入已保存内容。
- 未保存离开时，弹窗确认是否放弃修改。
- 不自动覆盖原始 AI 输出。
- 再次生成属于新的生成请求，需明确提示消耗 1 次额度。

#### 重新生成确认文案

**重新生成将消耗 1 次额度，并创建一条新的结果记录。是否继续？**

按钮：

- 取消
- 继续生成

#### 失败与恢复

- 结果不存在：提示返回历史记录。
- 网络加载失败：提供重试。
- 任务尚未完成：展示实时任务状态。
- 结果已被用户删除：不再显示正文。

### U05｜历史记录页

**页面目标：** 帮助用户快速找回已生成的文案。

#### 页面结构

1. 标题「历史记录」。
2. 筛选项「全部」「已保存」。
3. 历史记录列表。
4. 分页加载状态。
5. 空状态。

#### 列表卡片字段

- 模板名称。
- 内容摘要。
- 创建时间。
- 保存状态。
- 右侧操作入口。

摘要仅展示必要字数，不在列表完整暴露用户长文本。

#### 交互规则

- 点击记录进入结果详情。
- 点击更多可选择删除。
- 删除前必须确认。
- 删除正文不等于删除必要的订单、额度账务审计记录。
- 列表每页默认加载 20 条。
- 加载更多时保持已加载内容。

#### 空状态

**灵感会留下痕迹。**

你生成的文案将在这里方便查找。

按钮：**去写一篇**

### U06｜套餐购买页

**页面目标：** 让用户清楚了解套餐内容与有效期。

#### 页面结构

1. 标题「选择适合你的额度」。
2. 当前额度信息。
3. 套餐卡片。
4. 购买说明。
5. 购买协议入口。
6. 支付按钮。

#### 初始套餐展示

| 套餐 | 价格 | 权益 | 有效期 |
|---|---|---|---|
| 每日免费额度 | 免费 | 每天 5 次成功生成 | 北京时间每日重置 |
| 轻量包 | ¥9.9 | 50 次 | 初始方案为不设固定到期日 |
| 进阶包 | ¥19.9 | 300 次 | 购买后 30 天 |

以上为 PRD 初始商业方案，正式上线以实际审核通过并发布的套餐配置为准。

#### 重要说明

购买页必须清楚展示：

- 套餐次数。
- 有效期。
- 使用限制。
- 是否自动续费：**否**。
- 退款规则。
- 支付完成后的到账说明。

如启用单日成功生成次数上限，必须在购买前明确披露，不得隐藏在深层协议中。

#### 支付交互

- 点击套餐卡片切换选中状态。
- 点击「确认支付」发起微信支付。
- 支付成功后，以服务端确认结果为准更新额度。
- 支付取消返回套餐页。
- 支付结果不确定时展示「正在核实支付结果」，不可直接标记成功。
- 不允许连续重复创建相同支付请求。

## 六、10 个模板的表单体验规范

| 模板 | 主要输入区 | 建议交互 |
|---|---|---|
| 小红书标题 | 主题、核心卖点、受众、风格 | 简短字段 + 风格单选 |
| 小红书文案脚本 | 主题、主要内容或卖点、受众、风格 | 多行输入 + 风格单选 |
| 短视频口播稿 | 主题、核心信息、时长、风格 | 时长按钮组 |
| 朋友圈文案 | 主题、使用场景、语气、目标篇幅 | 场景选择 + 文本输入 |
| 文字润色 | 原文、润色目标 | 大文本框 + 目标单选 |
| 工作周报 | 已完成工作、工作成果、问题、下周计划 | 分区表单 |
| 会议纪要 | 原始会议记录、会议主题等 | 大文本框，明确不支持音频上传 |
| 工作邮件 | 写信目的、收件人角色、要点、语气 | 结构化输入 |
| 作文提纲 | 题目、学习阶段、写作方向、提纲结构 | 简短输入 + 提纲偏好 |

**字段名称、必填关系、字符限制以 PRD 已冻结定义为准。** 本文规定的是视觉呈现和交互方式，不擅自改变产品范围。

## 七、关键交互流程

### 7.1 首次使用流程

进入小程序 → 浏览首页 → 选择模板 → 填写表单 → 点击生成 → 按需登录 → 提交任务 → 查看结果。

要求：

- 登录前已填写的内容不丢失。
- 不强制用户在首页登录。
- 不在首次进入时强制展示付费弹窗。

### 7.2 额度不足流程

点击生成 → 服务端返回额度不足 → 展示不足说明 → 查看套餐 → 支付成功且服务端确认 → 返回原表单 → 用户主动重新提交。

**不得在支付成功后未经确认自动消耗额度生成。**

### 7.3 生成失败流程

提交 → 任务失败或超时 → 展示失败原因的用户友好描述 → 告知额度未扣除 → 用户可重试。

后台必须保证对应额度预占已释放，前端不得仅凭自身判断修改额度数字。

### 7.4 关闭小程序后恢复

用户提交任务 → 离开小程序 → 后台继续执行 → 用户再次进入历史页或结果页 → 根据服务端状态恢复。

不要求用户始终停留在加载页面。

## 八、动效规范

### 8.1 动效原则

**动效服务于状态反馈，而不是视觉表演。**

| 场景 | 建议时长 |
|---|---|
| 按钮反馈 | 100–150ms |
| 卡片状态变化 | 150–200ms |
| 内容淡入 | 180–240ms |
| 弹层出现 | 200–250ms |

### 8.2 禁止事项

- 不使用持续旋转的装饰性图形。
- 不在生成过程中播放大量文字飞入动画。
- 不使用复杂页面转场延迟操作。
- 不将「生成成功」设计成全屏庆祝动画。

## 九、无障碍与适配

### 9.1 可读性

- 正文与背景的对比度建议达到 WCAG AA 的相关要求。
- 重要信息不能仅通过颜色区分。
- 表单错误同时提供文字说明。
- 避免过小的点击区域。
- 长文本支持系统字体缩放后的合理布局。

### 9.2 设备适配

设计基准为 750rpx 宽度。

需要验证：

- 常见 iPhone 屏幕。
- 常见 Android 微信设备。
- 刘海屏与底部安全区。
- 微信胶囊按钮占位。
- 软键盘弹出时底部操作栏。
- 长文案溢出与换行。
- 不同系统字体渲染差异。

### 9.3 页面安全区

底部固定按钮必须预留安全区，不得遮挡最后一个输入字段或结果内容。

优先使用稳定的原生导航能力；确需自定义导航栏时，统一封装并测试微信胶囊区域。

### 11.3 设计 Token 管理

- `styles/tokens.less`
- `styles/typography.less`
- `styles/components.less`
- `components/*`

后台与小程序可共享设计语义，但不要求直接共享样式文件。

## 十二、文案与微交互规范

### 12.1 语言风格

采用：

**清楚、友好、克制、有帮助。**

避免：

- 夸张承诺。
- 过度卖萌。

- 技术错误直接暴露。

## 十四、设计冻结结论

文案轻工坊 V1.0 的 UI 不以视觉炫技为目标，而是通过以下方式形成长期耐看的高级感：

**少而准确的颜色、稳定的排版比例、舒适的留白、精细的组件状态，以及顺畅可靠的交互。**

最终视觉方向冻结为：

**轻纸墨绿 · 极简编辑器风格。**

后续设计迭代应优先优化可用性与细节，而不是频繁更换视觉主题。

**文档结束。**
